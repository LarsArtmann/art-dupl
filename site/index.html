How It Works

From Source to Clones in Six Steps

A concurrent pipeline transforms your Go source into actionable clone detection results.

01
Source Files
Scan Go and Templ files from your project paths
02
AST Parse
Parse into abstract syntax trees with concurrent workers
03
Transform
Serialize AST to language-agnostic token sequences
04
Suffix Tree
Build compressed suffix tree for O(n) duplicate search
05
Detect
Find repeating patterns above the token threshold
06
Output
Format results as text, HTML, JSON, or plumbing
Features

Built for Serious Codebases

Everything you need to find and eliminate code duplication.

Suffix Tree Detection

AST-level structural analysis using compressed suffix trees. Finds exact and near-miss clones that regex tools miss.

Core

Semantic Awareness

Default mode matches by identifier names and receiver types. Distinguishes CrushMode.IsValid from SafetyMode.IsValid.

Default

Multi-Method Detection

Run suffix tree and hash-based detection simultaneously. Combine results for comprehensive coverage.

Advanced

Smart Filtering

Auto-detects and filters SQLC and Templ generated code. Custom glob patterns for your project's conventions.

Smart

Rich Output Formats

Text, HTML with syntax highlighting, structured JSON for CI/CD, plumbing for scripts, and stats with CSV export.

Detection Methods

Choose Your Detection Strategy

Three modes to match your workflow. Run individually or combine for maximum coverage.

Suffix Tree

AST-based structural analysis using compressed suffix trees. Finds clones by code structure, ignoring literal values.
