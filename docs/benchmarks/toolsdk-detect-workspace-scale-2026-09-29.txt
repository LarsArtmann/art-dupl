## Verdict on a Spec-level timeout field (TODO D1)

**Not needed.** Detection at multi-module workspace scale sits ~100x under
BuildFlow's 60 s performance budget, and the SDK path already honors
`context.Context` cancellation end to end (`FindClones(ctx, ...)`; covered by
the provider ctx-cancellation test). A consumer that needs a bound can wrap the
Detect call in `context.WithTimeout` — the idiomatic Go mechanism — so a
`Spec.Timeout` field would be redundant plumbing in the toolsdk contract.
Re-evaluate only if a workspace 100x this size (or a pathological input class)
measurably regresses.
