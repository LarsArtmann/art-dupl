04Totally Fucked Up

Caught in time

go.sum trim would have dropped required checksums

go.sum — 47 lines removed by the prior session

The previous session's working tree had a go.sum with 47 lines removed. Those lines are required test-dependency checksums (e.g. stretchr/testify, gkampitakis/go-snaps, joshdk/go-junit, mfridman/tparse, tidwall/*, zeebo/assert). go build/go test masked it because Go lazily re-fetches missing checksums, but it is not a valid committed state. Resolution: go mod tidy restored them exactly to HEAD, and no broken trim was committed. The only real change needed was the stale flake.nix vendorHash bump (IcR8… → CIH0…), which was kept.

Lesson: Always run go mod tidy and diff against HEAD before committing a go.sum change. A passing go build is not proof that go.sum is complete.

07Top #1 Open Question

When do we actually remove the six deprecated --include-* flags?

They are hidden and emit a deprecation warning, but they still parse and work. I cannot determine the right removal cadence from the codebase alone: it depends on how many external users / CI pipelines / config files reference the old names, and whether a major version bump is the intended cue. Options:

  • Keep indefinitely (cheap, zero breakage, but permanent alias surface).
  • Remove at the next minor (clean, but risks silently breaking configs that set "includeSqlc": true in JSON — though config-file keys are separate from flag names).
  • Remove at a major bump (safest semver-wise, deferred).

Decision needed: what is the deprecation policy for CLI flags in this project, and is there a major version planned where the legacy flags should be deleted?
