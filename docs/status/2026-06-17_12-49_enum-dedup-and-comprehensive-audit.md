## d) TOTALLY FUCKED UP

### 1. Nix `vendorHash` Mismatch — **CI IS BROKEN**

```
nix flake check → error: hash mismatch in fixed-output derivation
  specified: sha256-P1MZ/PxmF3IUGLe9ycH7JuNOw6AsiiVx9r8rgoKKz9Q=
     got:    sha256-IcR8IPln7ZBB+QJP2MZKFMdr0204pgdH9IA/lIbrpjA=
```

The `vendorHash` in `flake.nix` is stale — it doesn't match the current `go.sum`. Per AGENTS.md: **fix is** `set vendorHash=""`, run `nix build`, copy the correct hash. This means **reproducible CI is down** until someone updates the hash.

### 2. Pre-existing `gosec G304` Lint Warning

`cmd/util.go:87` — `os.ReadFile(path)` triggers gosec's file-inclusion check. This is a **false positive** (path comes from CLI args scanning the user's own codebase, not untrusted input), but `just check` returns exit code 1 because of it. Needs a scoped `//nolint:gosec` with justification, or input validation that satisfies the linter.

**Note:** Both of these are pre-existing — confirmed by stashing the session's changes and reproducing on the clean tree.

## e) WHAT WE SHOULD IMPROVE

### Architectural

1. **Monolithic `printer/` package** — 50 files is too many. Splitting into `printer/stats/`, `printer/html/`, `printer/analyze/` would improve navigability and compile times.
2. **Three parallel Clone types** — Every clone flows through 3 DTOs. Consolidation would eliminate mapping boilerplate and the risk of drift.
3. **`actionability.go` ↔ `syntax.Node` coupling** — The only remaining direct import of AST internals in the printer layer.

### Type Safety

4. **`ProcessedClone` uses raw `string`/`int`** for filename and line numbers. Domain types `Filepath` and `LineNumber` exist but aren't used here. ~25 call sites to update.
5. **`sdk/pkg-utils` glob overlap** — Was fixed once; keep an eye on `.go-arch-lint.yml` as packages grow.

### CI/DevOps

6. **Nix vendorHash drift** — No automation to detect this before merge. Could add a periodic check or a `just update-vendor-hash` recipe.
7. **`just check` fails** on gosec false positive — either suppress or refactor to satisfy the linter.
8. **No performance regression suite** — Semantic mode got 9x faster, but there's no benchmark gate to prevent regressions.

### Code Quality

9. **`report_templ.go` is 1423 lines** — generated code, but if the templ source is that large, consider splitting the component tree.
10. **Templ has no semantic mode** — `syntax/templ/` matching is purely structural. Noted limitation, but limits templ clone quality.

## g) Top #1 Question I Cannot Figure Out Myself

> **Should `pkg/artdupl.Clone`, `printer.CloneGroup`, and `domain.ProcessedClone` be consolidated into a single canonical type — and if so, which one wins?**
>
> The three types exist for different reasons: `ProcessedClone` is the internal domain truth (validated, typed), `CloneGroup` is the JSON serialization DTO (printer-owned), and `pkg/artdupl.Clone` is the SDK's public-facing type (independence from internal packages). Each has a legitimate architectural justification. Consolidating risks breaking either the JSON contract or the SDK's type independence — but maintaining three parallel types means every new field must be added in three places and mapped twice.
>
> I need your call: **Is the goal zero mapping boilerplate (consolidate to one type + projections), or strict boundary isolation (keep three types, accept the boilerplate)?** This decision blocks 2 of the High-Priority TODO items and shapes the next architecture sprint.
