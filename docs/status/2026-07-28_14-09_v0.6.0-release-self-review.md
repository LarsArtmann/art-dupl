## E) WHAT WE SHOULD IMPROVE

### Process Improvements

1. **The tagliatelle/exhaustruct daemon regression is now a 5x recurring failure.** The pre-commit hook guard is not working. The daemon bypasses hooks. Need a different mechanism: either a CI check (already exists via `nix flake check` → `art-dupl-disabled-linters` check), or remove the daemon's write access to `.golangci.yml`, or add a git `pre-receive` server-side hook.
2. **The daemon makes release commits unreliable.** RELEASE.md says to commit manually, but the daemon races. Consider temporarily disabling the daemon during releases, or using a dedicated release branch that the daemon doesn't watch.
3. **No release artifacts.** Every release since v0.1.0 ships source-only. Consider adding a release workflow (`.github/workflows/release.yml` exists but is unused) or at minimum attaching the nix-built binary.
4. **The RELEASE.md checklist doesn't account for the daemon.** Steps 3 ("Do NOT commit via the daemon") is aspirational — the daemon will always win the race. The checklist needs a realistic mitigation.

### Code/Docs Improvements

5. **AGENTS.md says "22 patterns"** — should be 29. The number is stale even though individual pattern descriptions were updated.
6. **HOW_TO_USE.md lacks sections** for the extractability engine, `confidence` field, and `low-confidence` explain label.
7. **`runtime.Caller(0)` pattern** — this is the SECOND time trimpath broke test path resolution (the bench test had it too). All `runtime.Caller(0)` usage in tests should be audited and replaced.
8. **The `countNodes`/`countAllNodes` duplication** was "fixed" with an `//art-dupl:accept` directive, but the daemon already inlined `countAllNodes`. The accept directive may be masking a real issue or may be unnecessary now.
