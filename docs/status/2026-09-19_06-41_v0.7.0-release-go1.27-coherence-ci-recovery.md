## d) TOTALLY FUCKED UP

Radical-honesty section — things I broke, got wrong, or mishandled this session.

1. **I introduced a data race that reached CI.** `TestFormatTokenPosition` ran parallel
   subtests sharing one lazy line-table map; the race detector flagged it and tainted a
   dozen unrelated tests in the Race Test job. Root cause: I wrote `t.Parallel()` subtests
   around a shared lazy-cache without thinking about the write-on-first-insert. Fixed by
   giving each subtest its own cache. Lesson: run `-race` locally before pushing — the gate
   has it and I skipped it once.
2. **I pushed a syntax error into a test file.** Applying the modernize `embedlit`
   suggestion, I wrote `CloneRef: { ... }` (type elision — not what the analyzer proposes)
   without compiling first; the compiler rejected it ("missing type in composite literal").
   Recovered by reverting, then verifying the actual Go 1.27 promoted-literal semantics
   against a scratch program, then using `golangci-lint --fix`. Never push unverified
   mechanical rewrites.
3. **A prefix-ambiguous perl one-liner corrupted example_test.go.** `s/\tclient, err :=
   paperless.New(/…/` matched inside longer lines, splicing the accept marker mid-string
   literal. Repaired by stripping all markers and re-applying with anchored replacements.
   Bulk replaces must anchor to line boundaries or use the formatter/fixer tooling.
4. **An over-wide edit deleted an assertion block.** My `old_string` in
   config_validation_test.go spanned past the target and silently removed the error-check
   body; caught on the next build, restored. Edits must include only what changes.
5. **Tag collision on v0.7.0.** I created the local tag without checking the remote; a
   concurrent session had already pushed `v0.7.0` two minutes earlier. My push was rejected;
   both tags pointed at the identical commit, so I discarded mine and accepted the remote
   (bare "v0.7.0" message). If the commits had differed, this would have been a genuine
   release incident. `git ls-remote` before tagging is now mandatory practice.
6. **tmp_probe/main.go leaked into a daemon commit** and failed arch-lint on CI ("not
   attached to any component"). I created a scratch probe inside the repo, deleted it locally,
   but a daemon auto-commit had already captured it. Scratch files belong outside the repo
   (or in gitignored paths).
7. **I retyped a commit hash instead of copying it** (`71833527c19a…` vs the real
   `7183352045a3…`), producing a 404ing nix flake input. Fixed immediately; hashes are copy
   operations, not memory operations.
8. **Twice I misread my own rg output because of a flag typo.** `rg -rln` sets `-r ln`
   (replace matches with "ln"), corrupting displayed results. Both times I nearly acted on
   the corrupted text and both times verified against the raw file first. Stop typing
   `-rn`/`-rln` reflexively.
9. **The repo sat with red CI for ~10 hours before I looked.** The morning commit (484152fa,
   before my session) broke `go build`, gopls, golangci, and all CI; I discovered the breakage
   only via LSP diagnostics and discovered the CI state only at release prep. First-motion
   for any session: `go build ./...` + `gh run list`. Branch protection / failure alerts are
   also absent (nothing forced anyone to look).
10. **CHANGELOG churn.** My first insertion created duplicate `### Changed`/`### Added`
    headers under [Unreleased]; needed a restructure pass. Also the first arch-lint.yml edit
    dropped the `runtime` import context on version_cmd.go (a partial-file view), caught by

11. **Seven CI cycles burned on Windows/macOS issues** because I never proactively grepped

## e) WHAT WE SHOULD IMPROVE

1. **Session pre-flight ritual.** `go build ./...` + `gh run list --limit=5` before any work.
   Would have surfaced the broken toolchain AND the red CI in minute one instead of hour two.
2. **Verify-before-mechanical-edit.** Any analyzer-suggested rewrite: apply via the fixer
   tool (golangci `--fix`), then build — never hand-transcribe the suggestion from its
   message.
3. **Race-before-push.** `go test -race ./cmd/ ./bdd/` locally before every push touching
   cmd/bdd. The gate has it; my one skip produced a CI-tainting race.
4. **Cross-platform pre-check.** Grep for `filepath.Separator`, `strings.Split(_, ":")`,
   `\\`-literal path building, and `sed -i` in any code/tests claiming platform neutrality,
   before pushing to a matrix-CI repo.
5. **Daemon-aware committing.** Immediately before `git add`: `git status --short`;
   immediately after commit: `git show --stat HEAD` and re-add anything the daemon stole.
   Codify as a checklist (it cost three recoveries this session).
6. **Remote-ref checks for immutable operations.** Tags/releases: `git ls-remote` first.
   The skill says it; I skipped it under momentum.
7. **Scratch-code hygiene.** Probe programs go in `/tmp`, never inside the repo — the daemon
   commits anything that appears.
8. **Stale-"don't" hygiene in AGENTS.md.** The "do NOT bump to 1.27" note was correct when
   written and harmful when read. Point-in-time instructions in living docs need dates and
   re-verification triggers (this session proved the memory-file lesson again, from the
   other side: I *almost* reverted another session's legitimate work because of a stale note).
9. **Skill feedback loop.** Two durable lessons should flow back into skills:
   go-release (remote tag-collision check; explicit go-version pinning for tool-invoking
   jobs) and a possible new "cross-platform Go CI" checklist item in how-to-golang.
10. **Required checks / failure alerts.** A repo where CI can sit red for 4 days unnoticed
    needs branch protection with required checks, or failure notifications.
