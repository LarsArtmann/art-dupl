## g) TOP #1 QUESTION I CANNOT FIGURE OUT MYSELF

**Should the BuildFlow pre-commit hook only lint changed files, or should we fix all 20+ pre-existing lint issues first?**

The hook currently runs `golangci-lint run --fix` on the entire codebase. This means every commit fails because of pre-existing issues in files the developer didn't touch. Two approaches:

1. **Fix hook** (recommended): Change hook to `golangci-lint run --new-from-rev=HEAD~1` or similar, so only new issues block commits. Pre-existing issues tracked separately.
2. **Fix all lint issues first**: Fix all 20 golangci-lint issues, 22 TODOs, 4 committed binaries, SHA-1, fang v1 migration, AGENTS.md size — then the hook passes.

Option 1 is 1 hour. Option 2 is 2-3 days. But option 2 leaves the codebase actually clean. Which approach does the project prefer?
