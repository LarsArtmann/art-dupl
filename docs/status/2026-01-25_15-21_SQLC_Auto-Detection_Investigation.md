## Design Limitation Details

### Current Behavior

`FindSQLCConfigs()` only searches in exactly the paths provided:

| Command | Paths Searched | sqlc.yaml Found? | SQLC Filtered? |
|----------|----------------|-------------------|-----------------|
| `art-dupl /project-root` | `/project-root` | ✅ Yes | ✅ Yes |
| `art-dupl /project-root/db` | `/project-root/db` | ❌ No | ❌ No |

### Expected Behavior

Users typically run art-dupl in multiple ways:
1. `art-dupl .` (from project root) - ✅ Works
2. `art-dupl ./db ./internal` - ❌ Misses sqlc.yaml in parent
3. `art-dupl /path/to/project/db` - ❌ Misses sqlc.yaml in parent

### Impact

- **Low Impact:** Most users run from project root or provide root path
- **Medium Impact:** Users with multi-module projects or specific subdirectory analysis
- **Workaround Available:** Use `--filter-generated` flag explicitly

## Potential Solutions

### Option 1: Search Parent Directories (Recommended)

Modify `FindSQLCConfigs()` to search parent directories up to a reasonable depth:

```go
func FindSQLCConfigs(paths []string) (map[string]string, error) {
    configs := make(map[string]string)

    for _, path := range paths {
        // Search in provided path
        walkPath(path, configs)

        // Also search in parent directories (up to 3 levels)
        searchParentDirs(path, configs, 3)
    }

    return configs, nil
}

func searchParentDirs(path string, configs map[string]string, maxDepth int) {
    absPath, _ := filepath.Abs(path)
    current := filepath.Dir(absPath)

    for i := 0; i < maxDepth && current != absPath && current != "/"; i++ {
        if hasSQLCConfig(current) {
            // Found sqlc.yaml in parent directory
            configPath := filepath.Join(current, "sqlc.yaml")
            configs[configPath] = current
            return
        }
        current = filepath.Dir(current)
    }
}
```

**Pros:**
- More intuitive behavior
- Works with common usage patterns
- No breaking changes

**Cons:**
- More complex path logic
- Potential for false positives (rare)
- Performance impact (minimal)

### Option 2: Explicit Config Flag (Quick Fix)

Add a flag to specify sqlc config location:

```bash
art-dupl --sqlc-config /path/to/sqlc.yaml /project-root/db
```

**Pros:**
- Simple to implement
- No auto-discovery ambiguity
- Explicit control

**Cons:**
- Requires user to know config location
- Additional flag complexity
